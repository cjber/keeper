Keeps an Arch machine clean, with your agent doing the deciding.

Coding agents leave worktrees, build output, caches and transcripts behind. keeper finds what is safe to remove, proves it, and moves it to a trash you can undo.

GitHub Skill Changelog

Install

paru -S keeper-bin          # standalone binary
npm i -g @cillianb/keeper   # or from npm
npx skills add cjber/keeper # skill for your agent

In Claude Code, the plugin works too: /plugin marketplace add cjber/keeper, then /plugin install keeper@keeper. Then ask your agent:

Run keeper status, then keeper scan. Show me what is eligible and what is blocked, and why. Plan the low-risk items, then ask me before applying anything else.

To run it yourself, keeper opens a terminal wizard, and keeper timer install cleans up low-risk items every night.

Why keeper

  • It proves before it removes.A worktree counts as finished only when a merged pull request has the exact commit it sits on, or every commit is on the default branch. Anything else waits for approval.
  • Agents are the primary user.Every command returns JSON when piped, and each exit code names the next step. The wizard is a thin layer over the same calls.
  • Agents can protect their work.keeper hold outranks every scanner until it expires, so a session can mark a worktree it will return to.
  • Nothing is final until purge.Paths move to a trash and keeper undo restores them. Branches are deleted only at purge, and only if they have not moved.
  • It renices instead of killing.When the machine is overloaded, keeper names the commands holding the CPU and lowers their priority, so the work survives.

How it works

  1. scanRead-only. Every finding, with the blockers that keep it.
  2. reviewOptional. Your agent reads PRs and history, and holds unfinished work.
  3. planSaves the eligible findings up to a risk level.
  4. applyRescans, then moves only what is unchanged to the trash.
  5. purgeDeletes old trash for good and reports the space it freed.

What it cleans

Stale worktrees, AUR build clones, the pacman cache, orphaned packages, agent leftovers, build output, old transcripts, uv, pnpm, npm and bun caches, Docker images and build cache, snapshots and logs. It reports unused Docker volumes, CPU load and memory pressure, and leaves those calls to you.
